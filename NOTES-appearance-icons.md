## Architecture mismatch to resolve before drawing real icons

`exemple_gate.png` is **48x32 — not square, not 16x16**. That contradicts the
"fixed 16x16 square grid shared by every component" decision the current
architecture is built on (`PIXEL_GRID_DIM` in `src/constants.rs`, the hardcoded
`Extent3d` in `build_image` in `src/rendering/appearance.rs`). Open questions for
the user before continuing:

1. Does the appearance grid need to become non-square and/or per-asset-sized
   (revisits "fixed vs variable size", this time with a real reference disagreeing
   with the earlier "fixed" answer)? Or is 48x32 intentionally "3 grid cells wide,
   2 grid cells tall" — meaning a gate's rendered footprint should grow beyond the
   current single-cell `BODY_SIZE = GRID_CELL_SIZE * 0.9` in `src/editor/spawn.rs`,
   with placement/pin-offset math updated to match?
2. The cable references are 3 separate full textures per signal state (on/off/
   negative) rather than one texture procedurally tinted — cables currently stay as
   `Gizmos` line segments by explicit design (unchanged in this PR). Does the user
   want cables to move to pixel-art textures with distinct per-state art instead of
   a procedural tint? Bigger scope change, not decided.
3. `pin.png` and `node.png` similarly suggest pins (and maybe cable endpoints/nodes)
   might want real pixel art too, contradicting the earlier "pins stay procedural
   flat-color squares" decision from the original planning pass. Also not decided.
